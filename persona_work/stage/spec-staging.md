# 站位与镜头规格

> 交付物 ④（对应交接文件 §7）。**只出规格**。
> 所有数字都是**实测**得来，不是估的。实测脚本见文末。

---

## 0. 一句话

**站位 = 「裁掉透明留白 → 按内容定尺寸 → 底边贴到对话框上沿 → 水平分左右」**，
四步都是规则，没有需要逐个景调参的自由度（这也是原作的作风：机位高度程式化）。

---

## 1. 先更正两件交接文件里没写对的事

### 1.1 `_b` 全身版**在剧本里一次都没被引用**

实测：165 个 `.chs` 共引用 **6192** 个立绘标识，**含 `_b` 的 0 个**。

```
$ python persona_work/tools/sprite_sequence.py dump
persona_work/agg/sprite_sequence.json: 165 章, 6192 条不同立绘标识, 缺文件 0
# 再统计 _b：0 条
```

→ 交接文件 §6.1 问题 1「镜头何时切换 —— 看 `_b` 的有无」**无法照搬**，
   因为原作脚本里根本没有 `_b`。**「特写 / 全身」不是由脚本切换的。**

### 1.2 ★ `_b` 是「身体层」，**头部是透明抠空的**

实测（`head_width.py` / `head_alpha.py`）：

| 文件 | 画布 | 头部 alpha 覆盖 |
|---|---|---|
| `aok_a_12_02_00.mzp.png`（特写） | 1136×1018 | **44.2%** |
| `aok_a_12_02_00_b.mzp.png`（`_b`） | 2018×5844 | **21.0%** |

`_b` 图的头顶区域**整块透明**——脸是运行时另贴的一层（素材 `data02020/` 里就是这些
小尺寸的脸部件，如 `s_aok_a_12_02_00.mzp.png` = 151×445）。
这解释了为什么在对比表里 `_b` 的脸总是"黑块"。

→ **结论：`_b` 不能单独当立绘用。** 要用全身镜头，必须同时叠脸层；
   而脸层与身体的对齐参数**没有从素材里挖到**（见 `tech-notes.md` 议题 2）。

## 2. 画布与内容：**按内容 bbox 工作，不按画布**

原素材画布尺寸**不统一**（实测 `aok` 某服装行下就有 30 种画布），
原因：素材是从一张大图上按不同"裁切框"切下来的，**画布大小不代表立绘大小**。

真正稳定的是**内容**（alpha bbox 之后）的尺寸：

| 角色/服装 | 特写内容尺寸 | 说明 |
|---|---|---|
| 青子制服 / 羽绒服 | 631~757 × 763~1018 | 脸＋肩，头顶被原图裁掉 |
| 金鹿制服 / 便服 | 505~631 × 509~763 | 同上 |
| 有珠黑裙 | 624 × 509 | 同上 |

**头宽实测**（内容顶部 30% 区域的最宽连续不透明段）：
青子 631 / 696 px、金鹿 618 / 625 px、有珠 624 px —— **全部落在 618~700 之间**。

> ★ 这是本规格里最重要的一条实测：**特写立绘的"固有尺寸"本来就是统一的**（头宽 ~630px）。
> 所以**不需要按内容高度缩放**——直接 1:1 用，各表情之间不会跳大小。

## 2.5 ★ 对齐方式：**内容 bbox 中心对齐**（已实测验收）

### 2.5.1 为什么不按画布对齐、也不按"底边对齐"

- **画布不可用**：同一角色的画布尺寸有 30 多种（`254×256` ~ `2012×1272`），
  同一表情在 a/l/m/n/s 批次里画布都不同——按画布对齐会让脸乱跑。
- **底边对齐不够**：不同构图的脸在内容里的纵向位置不同（实测 `ey` 中位 0.33~0.52，
  **标准差 0.06~0.11**），说话时脸会上下跳几十像素。

### 2.5.2 采用规则（★ 最终）

```yaml
framing: closeup
source: 不带 _b 的立绘（= 原作脚本实际引用的那 6192 张）
preprocess: [alpha_bbox_crop]      # 1. 裁掉透明留白
scale: 0.70                        # 2. 统一缩放（见下）
anchor: bbox-center                # 3. 内容 bbox 的**中心**对齐画面锚点
x: 50%                             # 单角色居中（用户已定：只做单角色）
y: 50%
overflow: {top: visible, bottom: behind_dialog}
dialog_safe_top: 770
```

**为什么中心对齐就够**：特写立绘的内容 bbox **本身就是以脸为主体的**
（实测：青子制服特写的 bbox 高 1018、宽 697，脸占绝大部分）。
所以 bbox 中心 ≈ 脸中心，对齐后**各表情、各批次完全一致**，不会跳位。

**scale = 0.70 的推导**：青子制服特写 bbox 为 `697×1018`，
`×0.70` = `488×713` → 落在 `y = 540 ± 356`，即 **184 ~ 896**，
其中 `184~770` 是可见区（对话框之上），脸高约 713px ≈ 屏幕高的 66%，观感接近原作特写。
**实测验收图**：`final/stage_final_k0.7.jpg`（六景一张，脸位完全一致）。

> **备选值**：`k = 0.55` 时脸更小、留白更多（`stage_final_k0.55.jpg`），适合长对话；
> 建议做成可配置项，默认 **0.70**。

### 2.5.3 试过但放弃的方案：自动眼锚点

想过用"虹膜像素重心"做精确对齐（脚本 `eye_anchor_build.py`，产出 `eye_anchor.json`）。
**实测不可靠**：黑发/黑衣也是"高饱和暗色"，会被算成虹膜；
改良阈值后 `aok i3=12` 的 `ey` 标准差仍达 **0.194**，`koj i3=00` 达 0.197 —— 噪声太大。
→ **不采用**。`eye_anchor.json` 保留在交付物里仅作参考（可用于人工抽查单张），
**规格以 §2.5.2 的 bbox 中心为准**。

## 3. 特写规则（本皮肤的主力镜头）—— 见 §2.5.2

```yaml
framing: closeup
source: 不带 _b 的立绘（= 原作脚本实际引用的那 6192 张）
preprocess: [alpha_bbox_crop]
scale: 0.70
anchor: bbox-center
x: 50%
y: 50%
overflow: {top: visible, bottom: behind_dialog}
dialog_safe_top: 770
```

**为什么 x 用 50%**：单角色居中（用户已定）；青子/金鹿/有珠的 `ex` 中位都在 0.47~0.55，
居中后视觉重心自然，不需要额外偏移。

**验收图**：`final/stage_final_k0.7.jpg`（六景，脸位一致）。

## 4. 全身镜头规则（**当前不推荐启用**）

若将来要开全身镜头，规则如下（但必须先解决 §1.2 的脸层对齐）：

```yaml
framing: full
source: 带 _b 的立绘 + 对应脸层
preprocess:
  - composite: 脸层叠到身体层（对齐参数待挖）
anchor: bottom-center
x: 50%
y: 100%          # 贴底
scale: 0.45      # 见下
overflow: bottom # 腿被对话框遮住是正常的（原作也如此）
```

**scale 的推导**：同一表情的特写与 `_b` 版，**头宽比 = 0.509**
（`aok_a_12_02_00` 头宽 631px vs `aok_a_12_02_00_b` 头宽 1240px）。
所以 `_b` 按 **0.51** 缩放就与特写同尺度；再乘上"全身要比特写小"的意图，
取 **0.45** 左右。此值**未经画面验收**，属于待实测项。

> ⚠️ 若不做脸层合成，`_b` 只能表现为**无头身体**——不可接受。
> **这一条必须找用户决定**（见 `OPEN-QUESTIONS.md` Q3）。

## 5. 水平位置

| 场景 | x | 依据 |
|---|---|---|
| 单角色（本皮肤默认） | **50%** | 居中；青子脸本身略偏内容右侧，居中后视觉重心自然偏右一点点，接近原作 |
| 双角色同屏 | 左 **32%** / 右 **68%** | 交接文件 §7.1 待决项；**无原作可依**（脚本里只有立绘标识，没有坐标）→ 见 `OPEN-QUESTIONS.md` Q2 |
| 说话方高亮 | **不靠移位置**，靠**亮度/描边** | 交接文件 §7.3：差分切换不能改变元素尺寸或位置，否则抖动 |

> **重要**：`.chs` 里**没有坐标**（交接文件 §4.4 已指出「坐标在字节码操作数里」）。
> 本次尝试从字节码挖坐标**未成功**（详见 `tech-notes.md` 议题 1），
> 所以 §5 的 32%/68% 是**设计取值，不是照搬**。

## 6. 避让与遮挡

| 关系 | 规则 |
|---|---|
| 与底部对话框 | 立绘**允许**被对话框遮住下缘（这是常规做法）；脸的**眼睛行必须在 y < 0.55** 才可读 |
| 与满高暗带（长文时） | 暗带在立绘**之上**还是之下？→ 见 `OPEN-QUESTIONS.md` Q4。当前默认：暗带 `z-index` 高于立绘，但**中央 60% 恒定浓度区**避开眼睛行 |
| 与名字牌 | 名字牌贴对话框左上，与立绘不重叠（立绘居中时天然避开） |
| 多角色互遮 | 说话方永远在上层 |

## 7. 已知的坑（复核后仍成立）

| 坑 | 状态 |
|---|---|
| 差分切换不能改变元素尺寸 | **规格已消解**：头宽统一（~630px）＋固定 scale 1.0，切图前后尺寸完全一致 |
| 特写与全身比例差异极大（1.1:1 vs 1:2.9） | **规格已消解**：只裁 bbox 不缩画布；特写与全身分属两套规则，不混用 |
| 特写版的脸被裁切（只占画布右半） | **规格已消解**：统一裁 alpha bbox 后再居中，画布偏移的影响被完全消除 |
| 批次冗余导致同一表情有多张近似图 | **规格已消解**：优先级 `原作引用 > n > l > a > m > s`（见 `spec-switching.md` §5.2） |
| `_b` 5844px 露出哪一段 | **无法照搬**（原作 0 处引用）→ 见 `OPEN-QUESTIONS.md` Q3 |
