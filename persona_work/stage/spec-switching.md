# 表情切换逻辑规格

> 交付物 ⑤（对应交接文件 §6）。**只出规格，不写实现**。
> 上游依据：`docs/13-交接-表情切换与站位.md`、`persona_work/agg/sprite_sequence.json`、
> `persona_work/expressions/scene_frames.md`。

---

## 0. 一句话

**输入是「当前这句台词 + 谁在说」，输出是「用哪一张立绘」。**
分级决策：先按**说话人**选角色，再按**槽位**选表情，最后按**帧号表**取文件。

---

## 1. 数据通路（五级）

```
① 取文本     DSH 流式输出的当前句（见 §2 分句规则）
      ↓
② 定说话人   谁在说？（见 §3；主角皮肤下 99% 是女主角）
      ↓
③ 定槽位     12 个情绪槽位之一（见 §4 分类器）
      ↓
④ 查帧号表   (角色, 服装行 i3, 槽位) → 帧号 v（见 expressions.json）
      ↓
⑤ 取文件     (角色, 批次, i3, i4, v) → .mzp.png + 站位（见 stage.json）
```

> **④⑤ 是「照搬」的部分**，全部可从 `sprite_sequence.json` 与素材目录机械推导，
> 不需要任何创造性判断。真正需要设计的是 **① ② ③**。

---

## 2. ① 取文本：分句规则

| 项 | 规格 | 理由 |
|---|---|---|
| 粒度 | **一句一判**（不是一段一判） | 原作调度表的疏密实测：`2_3.chs` 一章 55 个立绘标识对上百句台词，**平均 2~3 句换一次表情**；不是每句都换 |
| 分句符 | `。！？…—～` 及换行；`，、` **不**断句 | 中文语料实况 |
| 超长句 | 超过 **40 字**按 `，` 二次切分（沿用 `dsh-galgame` 的 40 字阈值） | 与打字机节奏对齐 |
| 最短句 | 少于 **4 字**不单独触发切换，与上一句合并 | 避免"嗯。""哦。"造成表情抖动 |
| 取哪一段 | **当前正在流式输出的那一句**（不是整条消息） | 与打字机同步才有"说话时换表情"的观感 |

**滑动窗口**：分类器每次只看**当前句 + 上一句**（共 2 句）。理由：
单独一句常常没有情绪线索（「……」「是吗。」），带上一句才判得准；窗口再大就会滞后。

---

## 3. ② 定说话人

| 来源 | 处理 |
|---|---|
| 文本显式台词 | `「…」`／`“…”`／`角色名：` 前缀 → 归该角色 |
| 叙述体 | 归**女主角**（景对应的角色） |
| 无法判断 | 归**女主角**（默认） |
| 非对白时段（工具调用、思考、系统提示） | 女主角保持当前表情**不切换** |

> **本皮肤的实际约束**：DSH 里模型是自由生成的，没有原作那样的"角色名 + 台词"结构。
> 因此**默认只有一个说话人**（景的角色），多角色同屏属于可选增强（见 §7）。

---

## 4. ③ 定槽位：分类器

### 4.1 为什么必须做分类器

原作是**脚本硬编码**：「第 N 句 → 表情 X」。
DSH 里模型自由生成，**没有预写脚本**，所以必须有一个把任意文本映射到槽位的组件。
**这是本任务唯一真正"无原作可依"的设计点**（交接文件 §10.1 问题 5）。

### 4.2 三种可选实现（按代价从低到高）

| 方案 | 做法 | 优点 | 缺点 | 建议 |
|---|---|---|---|---|
| **A. LLM 分类** | 把「当前句+上一句+12 槽位定义+阈值表」给一个小模型，要它只输出槽位 id | 准、能读懂反讽与语境 | 每次切换一次调用，有延迟与成本 | ★ **首选**，配 200~300ms 超时 |
| **B. 规则匹配** | 用 `expression-notes.md` 表 2 的 74 条触发规则 + 关键词表 | 零延迟、零成本、可解释 | 覆盖窄，长句/反讽判不准 | 作为 **fallback 与预热**（首次切换先用规则出图） |
| **C. 两者结合** | 规则先给候选，LLM 只在候选有歧义时裁决 | 兼顾 | 复杂度略高 | ★ 工程上最稳 |

### 4.3 ★ 语言策略 —— **已解决：不需要翻译，官方简中剧本就在素材里**

**实测发现**：`game_scripts/ctd/data00200.hfa/` 下有**四份全文剧本**：

| 文件 | 语言 | 行数 |
|---|---|---|
| `script_text_ja.ctd` | 日文（原作） | 24135 |
| **`script_text_zc.ctd`** | **简体中文（官方汉化/汉化补丁）** | **24135** |
| `script_text_zt.ctd` | 繁体中文 | 24135 |
| `script_text_en.ctd` | 英文（官方英译） | 24135 |

**关键实测：四份文件行对行完全对齐**
- 行数完全相同（24135）；
- 空行位置集合完全一致（差异 0）；
- 抽样 7 处（第 0/1/100/1000/10093/23995/24133 行）逐行对应无误。

→ **所以「中文语料 ↔ 日文原文」的对照是现成的，不需要任何翻译步骤。**

**规格（据此定案）**：

1. **分类器直接用中文判定**，谓词表用中文写；
2. 谓词表的**来源**改为「官方中译 ↔ 日文原文对照」：
   既有的 74 条日文触发规则（`expression-notes.md` 表 2 带原文行号）
   **可以直接映射到中文措辞** —— 因为行号通用（两份文件行号一致）；
3. 不需要调用翻译模型，**省掉一次 LLM 往返**；
4. 参考项目「先转英文再分类」的建议在本项目**不适用**——那是因为他们没有官方译文，
   我们有。

> 落地方式：`expression-notes.md` 表 2 的每条规则都带日文行号，
> 用 `script_text_zc.ctd` 同行取中文原句，即可自动生成**中文谓词表**。
> 这是一次性的构建期工作，可完全脚本化（见 `OPEN-QUESTIONS.md` Q1 的收尾说明）。

### 4.4 谓词表（分类器的判定阈值、**直接来自 `expression-notes.md` 表 1**）

| 槽位 | 判定视觉特征 | 中文典型文本线索 |
|---|---|---|
| `neutral` | 眉眼平、嘴闭合、无张力 | 陈述、应答、沉默 |
| `smile` | 嘴角上扬（可闭眼），眉眼放松 | 开玩笑、打招呼、从容 |
| `laugh` | 张口露齿/闭眼仰头，笑肌明显 | 大笑、吐槽、起哄 |
| `angry` | 眉压低皱起、嘴角下压 | 被说教、被质疑、发火 |
| `glare` | 眼睑压低、半眼凌厉、视线锁定 | 冷笑、威胁、审视 |
| `surprised` | 睁大眼、眉上扬、口微张 | 意外、被吓到、听到意外信息 |
| `troubled` | 眉眼下垂、苦笑、手掩口、视线游移 | 为难、被戳中、尴尬 |
| `sad` | 眼睑下垂、嘴角下压、可闭眼 | 失落、回忆、道别 |
| `serious` | 眼神坚定直视、眉平、唇紧 | 正事、承诺、魔术/战斗 |
| `think` | 视线偏移（侧目/上视）、眉微动 | 琢磨、回忆、权衡 |
| `tired` | 半闭眼、眼下阴影、张口叹气 | 熬夜、抱怨、收工 |
| `shy` | 脸红、视线游移、可含手部动作 | 被夸、被感谢、告白 |

### 4.5 优先级（冲突时谁赢）

```
surprised > angry > glare > sad > shy > laugh > smile > troubled > tired > think > serious > neutral
```
- 强情绪**优先级高于**弱情绪：同一句里既有"生气"又有"平静"线索时取 angry。
- `neutral` 兜底：没有任何线索时用 neutral，**不要**随便挑一个强情绪。

### 4.6 迟滞与防抖（否则表情会抽筋）

| 机制 | 规格 | 依据 |
|---|---|---|
| **最小驻留** | 同一槽位至少停留 **1 句**；同一槽位连续命中**不重新设图** | 避免同一表情反复重设 |
| **迟滞** | 从 `neutral` 切到强情绪**立即**；强情绪切回 `neutral` 需**连续 2 句**非强情绪 | 强情绪要"抓得住"，弱化要"慢下来" |
| **置信度门限** | 分类器置信度 < 0.5 → **保持当前表情**，不切 | 宁可不换，不要换错 |
| **同一表情连续** | 连续命中同一槽位 **≥3 句** → 换用该槽位的**另一个帧号**（若有） | 照搬 SillyTavern 的"同一表情允许重复掷骰"防呆板 |
| **切换节流** | 两次切换至少间隔 **180ms** | 与打字机速度对齐，避免闪帧 |

## 5. ④ 查表：**以「具体文件」为键**（不是帧号）

### 5.1 ★★ 命名语义（**两轮实测推翻了交接文件 §4.1**）

交接文件写的是 `<角色>_<批次>_<i3 服装行>_<i4 表情>_<变体编号>[_b]`。

**实测结论：`i4` 和第 5 段 `v` 单独都不能确定表情。**

| 字段 | 实际含义 |
|---|---|
| `i3` | ✅ 服装行（这条是对的） |
| `i4` | **姿态 / 脸型通道**（同一套衣服下并存的多条通道，不同通道的脸型/机位不同） |
| `v`（第 5 段） | **每条 `(批次, i4)` 通道自己动画序列里的帧号** |

**证据一（跨通道不一致）**：

| 文件 | 图 |
|---|---|
| `aok_n_12_09_09` | 大怒（龇牙） |
| `aok_n_12_21_09` | 惊讶（睁大眼） |
| `koj_a_00_01_01` | 张口惊讶 |
| `koj_n_00_07_01` | 压眉瞪视 |

同样是 `v09`、`v01`，脸完全不同。

**证据二（通道内起点对齐）**：绝大多数通道的 `v00` 都是**同一张平静脸**
（`aok i3=03` 的 43/45 格、`koj` 两套服装的全部格）。
说明各通道确实是各自一条以"平静"开头的序列。

**证据三（各通道长度不同）**：`aok i3=03` 的 `n02` 通道覆盖 v00–v13（14 帧），
而 `a02` 只到 v04；`koj i3=01` 的 `a01` 到 v23、`l01` 到 v29。

> → **结论：查表必须用 `(角色, i3, i4, v)` 四元组，也就是具体文件名。**
> 本任务因此改用「景 → 具体文件 → 槽位」的对照表（`expressions.json`），
> 而不是「帧号 → 表情」的全局表。

### 5.2 取哪一张（可复现规则）

1. **优先取 `.chs` 里原作引用过的那个具体文件**（`sprite_sequence.json` 里全量可查）；
2. 若该槽位在此景下**没有**被引用过的文件 → 取**同一 `(批次, i4)` 通道内、语义最接近的帧**（同一条序列内相邻帧）；
3. 若该通道本身没有 → 取**同 `i3` 下另一个通道**里语义相同的文件；
4. 若整个 `i3` 都没有 → 走 §6 的 fallback 表；
5. **绝不跨服装行取**（`i3` 必须一致，否则换衣服）。

### 5.3 批次差异（必须知道）

同一语义的脸在 a/l/m/n/s 批次里**画风不同**（a 批线条锐、n 批柔和略带红晕），
个别通道连表情强度都不一样。→ **规格：同一景内固定一个批次**，不要混用，否则会"画风跳变"。

## 6. ⑤ Fallback（没有对应差分时怎么办）

12 个槽位不是每个角色、每套衣服都齐全（实测：青子 12/12、有珠 8/12、金鹿 2/12）。

| 缺失槽位 | 回退到 | 理由 |
|---|---|---|
| `laugh` | `smile` | 语义最近 |
| `sad` | `troubled` → `neutral` | 「失落」在有珠/金鹿身上表现为「困惑/平静」 |
| `shy` | `troubled` → `neutral` | 脸红→困扰 |
| `tired` | `neutral` → `think` | 疲惫→平静 |
| `think` | `neutral` | 思考用平静表现（原作有珠就是这么演的） |
| `angry` / `glare` | `serious` → `neutral` | 有珠原作无怒差分 |
| 任何槽位都缺 | `neutral` | **最终兜底，永远存在** |

> ⚠️ **金鹿只剩 2 个表情**（见 §8），所以她的 fallback 表几乎等于「全走 neutral/serious」。
> 这不是 bug，是原作素材限制——**必须如实呈现，不要自己造图补**。

## 7. 切换节奏与过渡（照搬参考项目的实测值）

| 项 | 值 | 来源 |
|---|---|---|
| 差分 crossfade | **120ms** | `Lanxing6480/dsh-galgame` 实测值（只借数值） |
| 说话弹跳 | **150ms × 2 次，幅度 12~20px** | 同上 |
| 立绘 anchor | **bottom-center** | 同上 |
| `prefers-reduced-motion` | **关闭全部动效** | 同上，无障碍 |
| 立绘切换时尺寸 | **必须不变**（先算好目标尺寸再切，不要"先切图再布局"） | 交接文件 §7.3 已知的坑 |
| 站位 | `alpha bbox 裁切 → scale 0.70 → 内容 bbox 中心对齐 (50%, 50%)` | `spec-staging.md` §2.5 |

## 8. 伪代码

```python
STATE = {"slot": "neutral", "sprite": None, "since": 0, "last_switch": 0}

def on_sentence(sentence, speaker_id, scene):
    if now() - STATE["last_switch"] < 180:      # 节流
        return
    if len(sentence) < 4:
        return                                   # 太短不触发

    ctx = prev_sentence + sentence
    slot, conf = classify(translate(ctx))        # ③ 分类（§4）
    if conf < 0.5:
        return                                   # 置信度门限：保持现状

    slot = apply_hysteresis(STATE["slot"], slot)  # §4.6 迟滞
    if slot == STATE["slot"]:
        STATE["since"] += 1
        if STATE["since"] >= 3:
            sprite = pick_variant(scene, slot)    # 换帧号防呆板
        else:
            return
    else:
        STATE["since"] = 0

    sprite = pick_sprite(scene, speaker_id, slot)   # ④ 查表（expressions.json）
    if sprite is None:
        sprite = pick_sprite(scene, speaker_id, FALLBACK[slot])   # §6
    if sprite is None:
        sprite = pick_sprite(scene, speaker_id, "neutral")

    stage = scene["stage"]                            # ⑤ 站位（见 stage.json）
    render_crossfade(STATE["sprite"], sprite, stage, ms=120)
    STATE.update(slot=slot, sprite=sprite, last_switch=now())


def pick_sprite(scene, who, slot):
    """★ 以「具体文件」为键查表；返回 None 表示无可用。

    expressions.json 的结构：
      scenes.<景>.slots.<槽位> = [{file, desc, conf, src}, ...]
    """
    bucket = EXPR["scenes"].get(scene["scene_id"], {}).get("slots", {}).get(slot)
    if not bucket:
        return None
    # 同一槽位多张时轮换（防呆板），按置信度优先
    order = sorted(bucket, key=lambda x: {"high": 0, "mid": 1, "low": 2}.get(x["conf"], 3))
    return order[STATE.get("roll", 0) % len(order)]["file"]
```

## 9. 与原作的差距（诚实清单）

| 项 | 原作 | 本规格 | 影响 |
|---|---|---|---|
| 触发源 | 脚本硬编码 | LLM 分类（有错判率） | 表情偶尔不准，可接受 |
| 调度粒度 | 作者逐句指定 | 模型逐句判 | 节奏会比原作"密"一些 |
| 语言 | 日文 | 中文 → 转译再判 | 多一层误差 |
| 镜头切换 | 原作按 `_b`？**实测：`.chs` 里 0 处 `_b` 引用** | 本规格只用特写 | 见 `tech-notes.md` 议题 2 |
| 多角色同屏 | 原作常有 | 默认单角色 | 见 `OPEN-QUESTIONS.md` Q2 |
