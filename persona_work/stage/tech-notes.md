## 议题 1 · 从字节码挖「站位坐标」—— **挖不到，需妥协**

| 项 | 内容 |
|---|---|
| 原目标 | 交接文件 §4.4「坐标在字节码操作数里，若能量出操作数布局即可批量导出」 |
| 本次做法 | ① 定位 `.chs` 的字符串表（末尾 nul 分隔 UTF-8 串，含 `$002510` 这类文本槽位）；<br>② 逐字节尝试把操作数解释为字符串地址（2/3/4 字节、`+0/-1/+BASE` 等多种映射）；<br>③ 检查所有 1595 个 `7f 00 00 00 <addr>` 型记录 |
| **实测结果** | **字符串表里只有立绘标识、背景编号、音效、文本槽位，没有任何浮点/坐标常量成组出现。**<br>把整个文件里所有 4 字节值扫一遍，能命中**字符串起始地址**的只有 **119 处 / 22 个不同字符串**——说明坐标不在字符串区，而且操作数编码也不是直接的地址引用。 |
| **结论** | ❌ **不能实现**。字节码是 Hunex 自定义格式，没有公开规格；本次没能在合理工作量内解出操作数布局。 |
| **替代方案** | 站位改为**设计取值**（`spec-staging.md` §3/§5），并用真实素材做九宫格预览人工选定。 |
| **要不要找用户** | 不需要——除非用户坚持"必须逐像素复刻原作的站位"，那样需要另立一个"逆向字节码"的任务。 |

## 议题 2 · `_b` 全身版 —— **必须找用户决定**

| 项 | 内容 |
|---|---|
| 交接文件的假设 | 「`_b` = 另一种镜头；看原作是否『说话方切特写』就能照搬」 |
| **实测打脸** | `.chs` 全库共引用 **6192** 个立绘标识，**含 `_b` 的 0 个**。<br>而且 `_b` 图的**头部是透明抠空的**（头部 alpha 覆盖 21%，特写是 44%），脸是运行时另贴的图层。 |
| **结论** | ⚠️ **`_b` 既没有被原作脚本用过、又不能单独当立绘用。**（要用就得自己把脸层对到身体层上，而这个对齐参数同样在字节码里。） |
| **建议** | **本皮肤只做特写镜头**（也就是原作脚本真正用到的那 6192 张），`_b` 全部不启用。 |
| **要不要找用户** | ✅ **要**。见 `OPEN-QUESTIONS.md` Q3。 |

## 议题 3 · ★ 立绘命名语义 —— **交接文件的假设是错的（已更正）**

| 项 | 交接文件的说法 | **实测更正** |
|---|---|---|
| `i4`（第 4 段） | 「表情」 | **是"姿态/脸型通道"**——同一套衣服下并存多条通道，各通道脸型/机位不同 |
| 第 5 段 | 「变体编号（同一表情的多张近似图，取景微调）」 | **是「每条 `(批次, i4)` 通道自己动画序列里的帧号」** |
| `i3` | 服装行 | ✅ 正确 |
| `_b` | 「另一种镜头」 | ⚠️ 是**身体层**（头部透明抠空）——见议题 2 |

**证据链（三重）**：

1. **跨通道不一致**（决定性）：同一帧号在不同通道是完全不同的脸 ——
   `aok_n_12_09_09` = 大怒（龇牙），而 `aok_n_12_21_09` = 惊讶（睁大眼）；
   `koj_a_00_01_01` = 张口惊讶，而 `koj_n_00_07_01` = 压眉瞪视。
2. **通道内起点对齐**：绝大多数通道的 `v00` 都是同一张平静脸
   （`aok i3=03` 43/45 格、`koj` 两套服装全部格）。
3. **各通道长度不同**：`aok i3=03` 的 `n02` 覆盖 v00–v13，而 `a02` 只到 v04。

> **结论：只有具体文件（`i3` + `i4` + `v` 三元组）才确定表情。**
> 所以本任务的表情对照表**以文件名为键**，不存在"帧号 → 表情"的全局表。

**影响**：交接文件 §5「对每个 `i4`，导出该表情的图」与 §5.1「取该 i3 行全部 i4 取并集」
**方向都不对**——那会把几十个不同的表情当成同一个。
本任务已按更正后的语义重建工具（`scene_expr_sheet.py` / `variant_strips.py` / `frame_consistency.py`）
与对照表（`expressions.json`、`expression-matrix.md`）。

**结论**：✅ 能实现，但**必须先说清楚**，否则后面所有表都是错的。
（这一条是本次最大的发现，也是交接文件最需要修订的地方。）

## 议题 4 · 批次冗余 —— **能实现，用原作引用优先**

| 项 | 内容 |
|---|---|
| 问题 | 同一 `(i3, i4, v)` 在 a/l/m/n/s 里都有，取哪张？ |
| 实测 | 同一码在不同批次**画风不同**（a 批线条锐、n 批柔和带红晕），个别码语义还有漂移。 |
| **规则**（可复现） | ① 优先取 `.chs` 里**原作引用过**的那张（`sprite_sequence.json` 全量可查）<br>② 没有就取**同一景内固定批次**（`n > l > a > m > s`）<br>③ **绝不跨 `i3`（服装行）取** |
| **结论** | ✅ 能实现。这就是"照搬原作"真正兑现的地方。 |

## 议题 5 · 特写与全身比例差异 —— **规格已消解**

| 项 | 内容 |
|---|---|
| 交接口径 | 「1.1:1 vs 1:2.9，锚点约定很难一次定对」 |
| **实测** | 特写立绘的**画布**尺寸有 30 多种（254×256 ~ 1892×1272），但**头宽高度统一**：<br>青子 631/696px、金鹿 618/625px、有珠 624px —— **全部落在 618~700**。 |
| **结论** | ✅ 能实现。**统一裁 alpha bbox + scale 1.0 + 底边贴到对话框上沿**，各表情之间尺寸完全一致，不会跳。 |

## 议题 6 · 特写版的脸被裁切 —— **规格已消解**

交接文件说「青子特写 1136×1018 的内容 bbox 是 `(505,0,1136,1018)`，只占右半，摆放时不能简单居中」。

**实测结论**：那是**画布**的偏移，不是脸的偏移。裁掉 alpha 留白之后，脸的横向位置在所有特写里是一致的。
→ 统一 `alpha_bbox_crop` 再居中即可，偏移问题消失。✅

## 议题 11 · 字节码解析的**意外收获**

虽然没挖到坐标，但本次把 `.chs` 的**字符串表**彻底摸清了，并据此做出核心工具 `sprite_sequence.py`：

- `.chs` 末尾是 **nul 分隔的 UTF-8 字符串表**，含：立绘标识（6192 条）、背景编号、音效 ID、文本槽位（`$00XXXX`）、标签（`A10_2_3_0000`）；
- **表内顺序 = 原作首次引用顺序** → 这就是"原作调度表"；
- 副产物：`sprite_sequence.py mix <章节>` 能打出**文本与立绘交错的完整调度流水**（`T:` / `S:` / `B:` / `E:`），
  用来还原"这句台词时该是谁的什么表情"。

**结论**：✅ 「照搬原作」这条路**部分成立**——**取哪张图完全可照搬**（这是最大的收益）；
**摆在哪里不可照搬**（坐标没挖到）。
